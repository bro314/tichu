## 1. Why & Goal

Today Tichu's BGA `#logs` panel is plain unstyled text and hides critical card-counting info whenever Phoenix substitutes inside a Pair, Triple, Running Pair, Straight, or Full House ([#142475](https://boardgamearena.com/bug?id=142475) by `flamesplash`), even though `Combo` already computes `$phoenixValue`. At the same time, Tichu's post-game statistics only track basic counts (`tricks_win`, bombs, Tichu bets) and omit high-interest round outcomes and special-card plays.

This plan delivers three cohesive, backwards-compatible improvements:

1. **Phoenix Combo Log Attribution (`#142475`)**: Emit localized `(with Phoenix as ${phoenix_rank})` phrasing in `playCombo` notifications whenever a non-single combo contains Phoenix, without touching single-Phoenix phrasing or breaking `Combo::$description` invariants.
2. **Accessible Rich `#logs` Badges**: Decorate specials (`Dragon`, `Phoenix`, `Dog`, `Mahjong`) and suited card tokens (`Q♠`, `10♥`, etc.) inside `Tichu::format_string_recursive` with styled light/dark `<span class="tichu-log-badge ...">` pills that preserve full plain text for screen readers and community tools.
3. **Additive Post-Game Stats**: Add Table `13` and Player `17..22` in `stats.inc.php` via a crash-proof `safeIncStat(...)` helper tolerant of pre-deploy live tables.

## 3. Architectural Decisions & Trade-offs

1. **Phoenix attribution in `completePlayCombo` / `NotificationManager::playCombo`, NOT `Combo::$description`**:
   - _Alternative rejected_: Appending `" (with Phoenix as ...)"` directly inside `Combo::checkPair`..`checkFullHouse`. That would break assertions in [`tests/ComboTest.php#L147`](file:///Users/brohlfs/git/tichu/tests/ComboTest.php#L147), [`tests/combo-validator.test.ts#L137-L155`](file:///Users/brohlfs/git/tichu/tests/combo-validator.test.ts#L137-L155), and [`local/integration-tests.php#L573`](file:///Users/brohlfs/git/tichu/local/integration-tests.php#L573), embed dynamically concatenated English into `$combo->description` right before Plan 02 moves `combo_name` to `{ log, args }` `clienttranslate` templates, and clutter `<tichu-last-played>` tooltips (`tichu-last-played.ts#L381`).
   - _Recommended_: Add `Combo::hasPhoenix(): bool`, keep `Combo::$description` and `LogManager::playCombo` canonical, and handle attribution in `completePlayCombo()` via 4 literal `clienttranslate(...)` templates whenever `(int) $combo->type !== SINGLE_COMBO && $combo->hasPhoenix()`, passing `"has_phoenix" => $combo->hasPhoenix()` and `"phoenix_rank"` (`"i18n" => ["combo_name", "phoenix_rank"]`) through `NotificationManager::playCombo`. Always showing `as ${phoenix_rank}` (e.g., `King full of 4 (with Phoenix as King)`) resolves ambiguity on Full House, Straight, and Running Pair while single Phoenix keeps its `"Phoenix a half step above..."` phrasing with zero doubling.
2. **ES5-strict-safe `format_string_recursive` with plain-text-preserving badges (`src/tichu.ts` & `tichu.css`)**:
   - _Alternative rejected_: Using `this.inherited(arguments)` (crashes in TypeScript ES5 strict mode at `dojo.js#L1725` and is absent in `bga-shim.js`) or empty CSS sprite `<span>` icons (breaks screen readers, breaks `shaneam/BGATichu` text scraping in `#logs`, and produces blank strings when `bga-shim.js#L2414-L2421` strips tags).
   - _Recommended_: Adopting inline log card styling like `Velonimo` (`docs/BGA_OPEN_SOURCE_ECOSYSTEM.md#L75`) and `bga-heat` notification decorators (`#L81`), delegate first to `(ebg as any)?.core?.gamegui?.prototype?.format_string_recursive?.call(this, log, args)` (matching `src/tichu.ts#L626-L673`), then run a lightweight ES5-compatible HTML-segmenting post-pass inside `src/tichu.ts` (zero runtime imports from `src/elements/`). Skipping HTML tags, `.playername` spans (so a user named `"Dragon"` stays untouched), and `.tichu-log-badge` spans prevents double-wrapping on recursive `{ log, args }` expansion while keeping readable text (`Dragon`, `Phoenix`, `Dog`, `Mahjong`, `Q♠`) inside every `<span>`.
3. **`safeIncStat()` tolerance & round-end card-point attribution (`tichu.game.php`, `stats.inc.php`)**:
   - _Alternative rejected_: Calling `$this->incStat(...)` directly or probing `$this->getStatTypes()`. Missing stat rows on pre-deploy live tables or cached config lag can throw mid-turn exceptions, and `_ide_helper.php` omits `getStatTypes()` (failing PHPStan level 5).
   - _Recommended_: Route all 7 new stats through `safeIncStat(string $name, int $delta, ?int $playerId = null)` which returns immediately on `$delta === 0` and wraps `$this->incStat($delta, $name, $playerId)` in `try/catch (\Throwable)` -> `$this->logProdWarn(...)`. Award `card_points_captured` only on normal rounds (`$doubleVic < 0`) AFTER `stEndRound#L1554` transfers the 4th player's `captured` pile to `$firstOutPlayer`, keeping player totals faithful to Tichu rules (double victories score 200 without card-point tallying).

## 4. 4-Way Live-Game Compatibility & Concurrency Audit

- **`OLD DB -> NEW PHP + NEW JS`**: Pre-deploy running tables lack DB `stats` rows for `13` / `17..22` and older `gamelog` entries lack `has_phoenix` / `phoenix_rank`. `safeIncStat` prevents exceptions on missing rows; `TichuNotificationMap['playCombo']` types `has_phoenix?` and `phoenix_rank?` as optional; `format_string_recursive` safely decorates historical logs client-side.
- **`OLD open JS tab <-> NEW PHP`**: Un-reloaded client tabs run stock `format_string_recursive` and `notif_playCombo`. Because `completePlayCombo` uses standard `${player_name}`, `${combo_name}`, and `${phoenix_rank}` BGA placeholders (`"i18n" => ["combo_name", "phoenix_rank"]`), stock clients interpolate text cleanly and `notif_playCombo` ignores additive payload keys.
- **`NEW open JS tab <-> OLD PHP` (rollback)**: Old server omits `has_phoenix` / `phoenix_rank` and `(with Phoenix as ...)` text; `Tichu::notif_playCombo` and `format_string_recursive` read optional args defensively and decorate special names seamlessly.
- **`NEW DB / actionlog -> OLD PHP + OLD JS` (rollback)**: Zero new states, `global` IDs, `dbmodel.sql` columns, `actionlog` actions, or `Combo::$description` formats are introduced; `LogManager::playCombo` remains unchanged and `stats` rows `13`/`17..22` are safely ignored after rollback.
- **Locking Invariants & `@thoun` Autopass**: Read-only JS formatting and existing server hooks add zero new endpoints or lock transitions (`acquireGameLockOrFail()` already guards `completePlayCombo`, `chooseDragonGift`, and `makeAWish`); `player_pass` autopass state (`AUTOPASS_NONE`/`ONCE`/`TRICK`) is untouched.
- **`<tichu-replay>` & 7-Surface SQL Remapping**: [`tichu-replay.ts#L457-L459`](file:///Users/brohlfs/git/tichu/src/elements/tichu-replay.ts#L457-L459) replays `playCombo` solely from `args.cards` + `args.points` (ignoring `log` at `#L518`). [`local/import-bug-sql.php#L690-L694`](file:///Users/brohlfs/git/tichu/local/import-bug-sql.php#L690-L694) already remaps `stats.stats_player_id` wholesale, and `remapGamelogPayload` (`#L806-L900`) needs no edits because `has_phoenix`/`phoenix_rank` hold no `player_id`s.
- **Studio `workspace.blocked-files` Compliance**: Strictly zero `$bgaContainer`, `\Bga\GameFramework\Old\Db`, `bga_*` tables, `Reflection*`, `eval`, network, or filesystem calls; `safeIncStat` calls only public `$this->incStat(...)` and `$this->logProdWarn(...)`.
