1. **Track A (Production Bundle Diet + Single-Pass ES2020 Build)**: Production [`tichu.js`](file:///Users/brohlfs/git/tichu/tichu.js) is currently `660,963 B` (`645.5 KB`) because [`src/tichu.ts`](file:///Users/brohlfs/git/tichu/src/tichu.ts#L12) statically imports [`src/studio-test.ts`](file:///Users/brohlfs/git/tichu/src/studio-test.ts#L1-L4734) (`4,734` lines of Playwright/`TichuBot` test scaffolding) and [`package.json`](file:///Users/brohlfs/git/tichu/package.json#L21-L24) concatenates ES5 `tsc` output with an ES6 `elements` bundle. 2. **Track B (Delete `tichu.view.php` & `tichu_tichu.tpl`)**: Eliminates empty 2018 boilerplate after sound files move to `sounds/`.

## 3. Architectural Decisions & Trade-offs

1. **Track A — Bundle Split & Target**:
   - **Recommended**: Single-pass `esbuild ./src/tichu.ts --bundle --format=iife --target=es2020 --outfile=tichu.js` with `toDojoPrototype(Tichu)` + separate `esbuild ./src/studio-test.ts --bundle --format=iife --target=es2020 --outfile=modules/js/studio-test.js`, dynamically loaded ONLY when `hostname` is `studio.boardgamearena.com`, `127.0.0.1`, or `localhost`.
   - **Alternative Rejected**: Full native ESM `modules/js/Game.js` migration (Tier 3 of old Plan 13) in the same pass — breaks live hot-swap caching (`tichu.js` stays cache-busted by BGA release) and forces rewriting every `dojo.subscribe`/`ajaxcall`/Dojo inheritance site simultaneously; save native `Game.js` for a tiny follow-up after Track C.
   - _Exemplar_: Matches [`docs/BGA_OPEN_SOURCE_ECOSYSTEM.md`](file:///Users/brohlfs/git/tichu/docs/BGA_OPEN_SOURCE_ECOSYSTEM.md#L79-L80) TypeScript bundler hygiene while respecting Studio's `modules/*.js` workspace allowlist and `"Use minified JS"` / `"Use minified CSS"` pipeline.

2. **Track B — `.view.php` / `.tpl` Removal Order**:
   - **Recommended**: Deploy Plan 13's `sounds/tichu_laser.{mp3,ogg}` first so [`ly_studio.js:28349-28382`](file:///Users/brohlfs/git/tichu/bga-platform/js/modules/layer/ly_studio.js#L28349-L28382) `preloadedSounds` auto-discovers `sounds/`, then delete `tichu.view.php` + `tichu_tichu.tpl` cleanly (plus `sftp rm` on Studio!). Keep `rehydrateModel()` idempotently mounting `<tichu-game>` inside `#game_play_area`.

3. **Track C — Autowired `act*` Rollout & Live-Tab Skew Trap**:
   - **Critical Verification**: `GameAction::performServerAction` (`171, 202`) + `bgaPerformAction` (`ly_studio.js:26668-26678`) send and `checkAction()`-verify the **full `"act..."` string** (`"actPlayCombo"`, NOT `"playCombo"`) when `.action.php` is absent. Deleting `tichu.action.php` in the same deploy where old open tabs still send un-prefixed `playCombo.html` rejects those pre-Release-N tabs (`BadMethodCallException` line `176`) until F5 refresh!
   - **Recommended Two-Release Strategy**:
     - **Release N (Expand)**: Add all `act*` methods on `Tichu` (with `#[CheckAction(false)]` on out-of-turn interrupts + **both** `actGiveTheCards` + `actGiveCards` and `actChoosePhoenix` + `actPhoenixPlay`), upgrade `local/` framework + contracts, update `states.inc.php` `possibleactions` (`act*` names), switch JS `takeAction` to `act*`, and delete `tichu.action.php` (+ `sftp rm`). **Zero-downtime variant**: keep a ~40-line `tichu.action.php` forwarding legacy non-`act` endpoints (`playCombo()`, `giveTheCards()`, ...) to `$this->game->act*(...)` during Release N and delete `tichu.action.php` cleanly in Release N+1 once Release N has baked; decide explicitly before deploy whether a 1-deploy F5 refresh for open old tabs is acceptable.
     - **Release N+1 (Contract)**: Switch remaining client/test calls (`giveTheCards`/`choosePhoenix`) -> canonical `actGiveCards`/`actPhoenixPlay`, remove legacy `actGiveTheCards`/`actChoosePhoenix` (and forwarding `.action.php` if deferred), and optionally relocate `Tichu` -> `modules/php/Game.php` (`namespace Bga\Games\Tichu` per `thoun/conspiracy` & `bga_duelly` in [`docs/BGA_OPEN_SOURCE_ECOSYSTEM.md:80,88`](file:///Users/brohlfs/git/tichu/docs/BGA_OPEN_SOURCE_ECOSYSTEM.md#L80-L88)) keeping cohesive `Game` class without splitting into 15 `States/*.php` micro-files.

4. **Track D — Light-DOM Tutorial Proxies vs. Flattening Shadow DOM**:
   - **Recommended**: Keep Lit Shadow DOM encapsulation in normal gameplay; render synchronized light-DOM `#bga_tutorial_*` proxy anchors inside `#game_play_area` **only** when `g_tutorialwritten?.mode` (`"edit"`/`"view"`) or `g_tutorialview` is set, plus freeze auto-timers and bypass `.disabler` pointer interception. Rewriting 16 Lit components to light DOM (`createRenderRoot() { return this; }`) would break slotted/scoped CSS across themes `0..10` cleanly for zero live-play benefit.
