## 1. Why & Goal

Live Tichu players currently only see cumulative team scores in `#player_board_<id>` and a transient `tableWindow` dialog (`"Result of this Round"`) at the end of each round (`tichu.game.php:1622-1692`). Once dismissed, players cannot review earlier rounds' card points, who called Tichu (`±100`) or Grand Tichu (`±200`), Double Victories (`+200`), or momentum swings — the exact request in [#36912](https://boardgamearena.com/bug?id=36912) (`13` votes).

Meanwhile, [`src/elements/tichu-score-board.ts`](file:///Users/brohlfs/git/tichu/src/elements/tichu-score-board.ts) only exists inside `<tichu-replay>` (`g_archive_mode`), couples directly to `window.model`, hardcodes `names[0] + names[2]` vs `names[1] + names[3]` and `r.scores.slice(0, 2)` instead of grouping by `player.team` (`0` vs `1`), uses untranslated `<td>Round</td>`, and breaks `html[data-theme="dark"]` with `tr.current { background-color: whitesmoke; }`.

Goal: Persist compact `roundScore` summaries in `actionlog` (zero DB migration), emit them on `newScores` / `getAllDatas()` (with pre-deploy running-game grace), refactor `<tichu-score-board>` into a pure team-aware, dark-mode-safe Lit component shared by `<tichu-replay>` and a `document.body`-mounted `<tichu-score-modal>`, and remap `roundScore.bets` in `local/import-bug-sql.php`.

## 3. Architectural Decisions & Trade-offs

1. **Persistence of `roundScore` in `actionlog` (Recommended)** vs. new table or parsing `gamelog`:
   - **Recommended**: Insert `roundScore` into `actionlog` (`varchar(16)` action `"roundScore"`, ~107–315 byte JSON payload easily within `log_arg varchar(1024)` — never embed player names!) right after `PlayerManager::updateScores($team_points)` and `PlayerManager::getScores()`, and before `NotificationManager::newScores(...)` and `nextState()`. At that point `log_round` equals the finished round (`1..N`). Zero `dbmodel.sql` change or `upgradeTableDb` migration needed.
2. **Pre-deploy running-game grace (`"Prior rounds cumulative total"` row)**:
   - **Recommended**: When `getAllDatas()` finds `roundHistory` missing earlier rounds (e.g., `firstRound > 1`, or `roundHistory` empty while `round > 1` or `teamTotals !== [0, 0]`), synthesize one `"Prior rounds cumulative total"` (`Rounds 1–K`) row whose `teamTotals` equals `firstRecorded.teamTotals - firstRecorded.teamPoints` (or current `player_score` per team if none recorded yet). Re-computing historical card points from `actionlog` is rejected because pre-Nov-2026 logs omitted `chooseDragonGift` recipients; exact `player_score` delta guarantees running totals match the scoreboard 100%.
3. **Pure Lit `<tichu-score-board>` + `document.body` `<tichu-score-modal>` (Recommended)** vs. `bga-score-sheet`:
   - Per [`docs/BGA_OPEN_SOURCE_ECOSYSTEM.md`](file:///Users/brohlfs/git/tichu/docs/BGA_OPEN_SOURCE_ECOSYSTEM.md#L138), reuse Tichu's native Lit stack (`Coinche` scorepad UX) rather than introducing `bga-score-sheet` DOM friction. Keep `<tichu-score-board>` free of global store subscriptions (props: `team0Label`, `team1Label`, `players`, `rounds`, `currentRound`, `compact`), mounted inside `<tichu-score-modal>` on `document.body` (`rescale()`-safe) and reused inside `<tichu-replay>`.
4. **Dark mode via CSS custom properties, NOT `:host-context()`**:
   - `:host-context()` fails in Safari and Firefox. Define `--tichu-modal-*` and `--tichu-row-*` tokens on `html` and `html[data-theme="dark"]` in `tichu.css` (referencing `--palette-bga-gray-*` from [`bga-shim.css`](file:///Users/brohlfs/git/tichu/local/css/bga-shim.css#L173-L246)) so colors inherit through Shadow DOM everywhere.

## 4. 4-Way Live-Game Compatibility & Concurrency Audit

- **1. `OLD DB -> NEW PHP + NEW JS`**: `getAllDatas()` handles zero `roundScore` rows via the synthetic `"Prior rounds cumulative total"` row when `round > 1` or scores are non-zero; `Tichu::getAllDatas` casts `team` via `Utils::parseInt` and TS tolerates string `"0"`/`"1"`.
- **2. `OLD open JS tab <-> NEW PHP`**: `NotificationManager::newScores($newScores, $roundScore = null)` keeps `newScores` as the exact same `{ [playerId]: score }` map; `roundScore` is strictly additive (`null` or object), so old tabs ignore it and keep playing until F5.
- **3. `NEW open JS tab <-> OLD PHP` (Rollback)**: `TichuGamedatas.roundHistory` and `TichuNotificationMap['newScores'].roundScore` are optional (`?`); `GameModel::hydrateFromGamedatas` defaults `roundHistory` to `[]` (synthesizing a prior-score row from `players` if `round > 1` or `score != 0`), and `applyNewScores` works when `roundScore` is `undefined`.
- **4. `NEW DB / actionlog -> OLD PHP + OLD JS` (Rollback)**: `LogManager::insert(0, "roundScore", ...)` keeps `log_round` and `log_trick` unchanged; all `OLD` PHP queries filter explicitly by `log_action IN (...)` (`combo`, `pass`, `phoenix`, `confirm`, `changePlayer`, `tichuCall`) and `getCurrentDbRoundAndTrick()`/`getCurrentRoundAndTrick()` only read `MAX(log_round)` / `log_trick > 0`, so `roundScore` rows are invisible to `OLD` PHP. If a round later finishes on `OLD` PHP and `NEW` returns, gap reconciliation injects a synthetic prior/unrecorded delta row matching `player_score`.
- **Concurrency, Autopass, Replay & Platform Guardrails**:
  - **Locks**: `stEndRound()` only executes inside an already-locked transition (`playCombo`, `chooseDragonGift`, or `zombieTurn` holding `acquireGameLockOrFail()`); `getAllDatas()` remains read-only (no `acquireGameLock()`). No new action endpoints or out-of-turn interrupts are added (`npm run test:race` unaffected, still verified).
  - **`@thoun` Autopass (`player_pass`)**: `stNewRound()`/`stNewTrick()`/`stNextPlayer()` `player_pass` invariants are untouched (`roundScore` inserts after scoring in `stEndRound`).
  - **`<tichu-replay>`**: `createScoreBoard(notifs, players)` uses `player.team`, handles `notif.args.roundScore` when present, and falls back for historical replays (`rawDelta - betDelta` sum `=== 200` uniquely identifies Double Victory vs `=== 100` normal rounds) while matching `tidyUpGamelogs` (which keeps `grandTichuBet`, `tichuBet`, `newScores`, and `playerGoOut` when bundled with `playCombo`).
  - **`local/import-bug-sql.php` 7 Surfaces**: Surface 4 (`actionlog.log_arg`) and Surface 5 (`gamelog.gamelog_notification`) both remap `'bets'` keys cleanly (working identically across two-phase `$tempMap`/`$finalMap` and `$directMap`).
  - **`ABSOLUTE NO-GO` Compliance**: Zero platform internals (`$bgaContainer`, `bga_*`, filesystem/process calls) outside `local/`; verified by `npm run test:contracts`.
